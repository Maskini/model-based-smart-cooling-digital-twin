# Browser dashboard

This static frontend runs Simulation entirely in the visitor's browser. There are no external fonts, libraries, backend requests on the simulation path. Live Hardware uses the existing authenticated Python API. Owner tokens remain in memory and are cleared on mode changes; no secrets are bundled.

`core.mjs` contains interchangeable browser simulation and REST adapters. Both feed one dashboard snapshot shape. The browser state machine, controller and Euler model are ports of the Python implementation, verified with 2,376 control cases and 45 thermal cases generated by `scripts/browser_parity.py`.

Browser calibration deliberately holds the ambient coefficient fixed; the Python fitter can also estimate it when observable. Both use bounded candidates, chronological holdout improvement, fresh-data verification and rollback. The local supervisor explains controller behavior and evaluates persistent model error. Live mode retains the Python supervisor and its model history.

Physics advances in one-second steps while the browser schedules timers. Background tabs may throttle or pause simulation; resuming does not jump forward by the entire missing wall-clock interval. History is bounded to 600 local samples; all local state resets on reload. Fan PWM is commanded/reported duty cycle, not measured RPM.

Run locally: `python -m http.server 8765 --directory web`. Generate and test parity with `python scripts/browser_parity.py` and `node --test tests/browser/core.test.mjs`.

Publish this directory to the `pages` branch and configure GitHub Pages to serve its root. Keep `.nojekyll`. No build step is required. After browser changes, regenerate that branch using `git subtree split --prefix=web`, then push its resulting commit to `refs/heads/pages`. The main implementation stays on `main`.
